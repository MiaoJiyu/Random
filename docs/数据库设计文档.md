# 数据库设计文档

本项目使用云端 MySQL（`random@your_ip:3306/random`）。后端通过 `mysql2` 连接池访问，启动时**幂等自动建表**，无需手动迁移。

---

## 一、连接与初始化

- 连接参数来自 `.env`（`DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME` / `DB_CONNECT_LIMIT`）。
- 连接池默认 10 个连接，`waitForConnections` 开启，`charset: utf8mb4`。
- `ensureSchema()`：`CREATE TABLE IF NOT EXISTS` 创建下表；若无任何激活配置则写入一份带示例数据的默认激活配置。
- 数据库不可达时后端不崩溃，前端以“云端离线”降级运行，本地功能正常。

## 二、表结构

### 1. `configs` —— 配置表

存储多份数字/权重配置，单一激活配置（无登录，所有用户共享）。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INT PK AUTO_INCREMENT | 配置 ID |
| `name` | VARCHAR(100) | 配置名称，默认“默认配置” |
| `data` | JSON | 配置内容 `{ mode: 'wheel'|'number', items: [{number, weight}] }` |
| `is_active` | TINYINT(1) | 是否激活（唯一激活），默认 0 |
| `created_at` | DATETIME | 创建时间，默认当前时间 |
| `updated_at` | DATETIME | 更新时间，自动更新 |

> 激活切换在事务内执行：`UPDATE ... SET is_active=0` 后 `UPDATE ... SET is_active=1 WHERE id=?`，保证唯一激活。

### 2. `history` —— 历史记录表

每次抽取的落库记录（与配置隔离，无登录）。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INT PK AUTO_INCREMENT | 记录 ID |
| `number` | INT | 抽取到的数字 |
| `weight` | INT | 该数字当时的权重 |
| `created_at` | DATETIME | 抽取时间，默认当前时间，索引 |

索引：`idx_created_at (created_at)`、`idx_number (number)`。

## 三、配置 data 结构约定

```json
{
  "mode": "wheel",
  "items": [
    { "number": 1, "weight": 10 },
    { "number": 2, "weight": 20 }
  ]
}
```

- `mode`：`wheel`（大转盘）或 `number`（数字闪动）。
- `items`：数字/权重对，整数；权重 ≤ 0 视为 1；后端写入与读取均做清洗。
- 概率 = `weight / 总权重`，在前端实时计算展示。

## 四、REST API 清单

统一返回格式：`{ code: 0, data, message }`（`code !== 0` 表示异常）。所有参数均使用参数化查询，避免 SQL 注入。

### 配置（config）

| 方法 | 路径 | 说明 | 请求体 / 参数 |
| --- | --- | --- | --- |
| GET | `/api/config/active` | 读取当前激活配置 | — |
| PUT | `/api/config/active` | 保存（就地更新）激活配置 | `{ name?, data }` |
| GET | `/api/config` | 配置列表 | — |
| POST | `/api/config` | 新建配置 | `{ name?, data }` |
| PUT | `/api/config/:id` | 更新配置 | `{ name?, data? }` |
| DELETE | `/api/config/:id` | 删除配置（删激活配置时自动激活其余第一条） | — |
| POST | `/api/config/:id/activate` | 激活切换 | — |

### 历史（history）

| 方法 | 路径 | 说明 | 请求体 / 参数 |
| --- | --- | --- | --- |
| POST | `/api/history` | 写入一条历史 | `{ number, weight }` |
| GET | `/api/history` | 分页查询（倒序） | `?page=1&pageSize=100`（pageSize 最大 500） |
| DELETE | `/api/history` | 清空全部历史 | — |
| GET | `/api/stats` | 分布聚合 | 返回 `{ total, distribution:[{number,count,avgWeight}] }` |

### 系统与模板

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查，含 `db` 连通状态 |
| GET | `/api/template.csv` | 示例导入模板下载（含 BOM，Excel 友好） |

## 五、统计 SQL 示例

```sql
SELECT number, COUNT(*) AS cnt, AVG(weight) AS avg_weight
FROM history
GROUP BY number
ORDER BY cnt DESC, number ASC;
```

## 六、前端历史上报可靠性

前端在抽取动画结束后异步 `POST /api/history`。若网络失败，记录写入 `localStorage` 队列（`random_history_queue`），下次 `/api/health` 返回云端在线时自动批量重放，避免云端抖动导致记录丢失。

## 七、部署

- **网页版**：`npm start`（或 `node server/index.js`），默认监听 `PORT`（3000），静态托管 `public/`。
- **桌面版**：`npm run electron`，主进程内嵌启动同一 Express 应用并分配空闲端口，渲染进程加载本机地址；前后端代码零差异。
- **打包**：`npm run build:win`（electron-builder NSIS），产物在 `dist/`。
